# Quality check 2026-11-01

The ten quality rules checked against the code, with evidence. Go 1.26.10, Windows 11, Intel Core
i7-13700H. The Go side reads files and stdin only; the eBPF programs run in the kernel and are
loaded only in CI, so several rules are about the C program or are not applicable (reason given).

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Every call can fail | pass | No network or database calls. File and stdin reads are bounded and every error is returned with context: `bpfdump.Parse` (`io.LimitReader`, `MaxInput` 16 MiB), `tpformat.Parse` (1 MiB scanner buffer), `cli.readDump` (refuses non-regular files), `probes.CheckKernel` (missing format file is an error, exit 1). The only ignored errors are `Close` on files opened read-only (`internal/cli/cli.go:154`, `internal/probes/catalog.go:114`), where nothing can be lost. In the C program every `bpf_map_lookup_elem` result is checked for NULL before use (`bpf/latency.bpf.c` `hist_add`, `tp_switch`, `tp_rq_complete`, `kr_fsync`). `scripts/probe-run.sh` runs with `set -euo pipefail`, reports a failed `bpftool prog loadall` as an `::error` annotation, and the CI jobs have 15-minute timeouts. |
| 2 | Writes safe to retry | pass | The CLI writes only to stdout. `probe-run.sh` removes the pinned programs and maps before loading and again on exit (`trap cleanup EXIT`), so a second run starts from the same state. In the kernel, start times are written with `BPF_ANY` (a repeated start event overwrites, it does not add), and each end event deletes its start entry, so one start is counted at most once. |
| 3 | No race conditions | pass | The Go code has no goroutines or shared state (`grep -rn "go func\|sync\." cmd internal`: none). In the kernel, histogram slots are per-CPU arrays incremented with `__sync_fetch_and_add`; the start maps are LRU hashes keyed per task, request or thread. A lookup-then-delete on the start maps can race with a new start event for the same key on another CPU; the cost is one lost or skipped sample, never a wrong bucket; LRU eviction under more than 10,240 in-flight starts loses samples the same way. Listed under known limitations. |
| 4 | Don't trust the clock | pass | Latencies are deltas of `bpf_ktime_get_ns()` (CLOCK_MONOTONIC), and only positive deltas are counted (`if (now > *start)`). The Go code reads no clock. No timestamps are stored or logged. |
| 5 | Read before changing | fixed | APIs used are the standard library (`go vet` clean on windows and linux) and libbpf/bpftool commands that CI runs. Found: `BPFTOOL` (read by the Makefile and `scripts/probe-run.sh`) and `BPF_CLANG` (Makefile) were not documented; the README "Run it" section now names both with their defaults. Every path the README lists exists. |
| 6 | Never break compatibility | pass | The JSON summary (`cli.Summary`) is unchanged; optional fields use `omitempty`. The input format is bpftool's JSON dump, and the tracepoint layouts are checked against the running kernel (`check-format`, exit 4 on mismatch) before anything is loaded. |
| 7 | One source of truth | pass | The kernel layout is written three times on purpose and tied together by tests: `FIELD_ASSERT` in C, the Go catalog, and the kernel's tracefs (`internal/probes/catalog_test.go` reads `latency.bpf.c` and compares every `SEC()`, map, `MAX_SLOTS` and offset). The histograms are the only copy of the data; user space reads them from the maps and keeps nothing. Go version: `go.mod` `go 1.23`, README "Go 1.23+; CI uses 1.26.10", both CI jobs 1.26.10: consistent. |
| 8 | Small changes, no secrets, validate input | pass | Secret scan (`grep -rniE "password\|secret\|api_?key\|token" --include=*.go cmd internal`): no matches. Inputs validated with clear errors: dump size, entry count, key and value width, hex byte form, duplicate keys, CPU count and overflow (`bpfdump`); format file size, field offsets and sizes, identifier form (`tpformat`); probe name, output format and flags (`cli`, exit 2). No new dependency. |
| 9 | Tests that can fail | fixed | No tautologies, skips or assertion-free tests (`grep -rn "t.Skip\|assert true"`: none). Mutation table below: 10 of 16 killed before; the 5 non-equivalent survivors now have tests that kill them. |
| 10 | Re-verify | pass | `bash .tmp/check.sh`: `gofmt` clean, `go vet` (windows and linux) clean, linux build ok, `tests passed: 40, failed: 0`, govulncheck v1.8.0 `No vulnerabilities found.`, `ebpf-latency-profiler: OK`, `CHECK PASS`. Fuzzing re-run for the proof image, 15 s per parser, 0 failures. The kernel side is verified by the CI `probes` job of this commit. |

## Known limitations

- The race detector is not run: the Go code has no goroutines, and the machine has no C compiler.
- Samples can be lost, never miscounted: a start entry evicted from a full LRU map (10,240 entries), or
  replaced by a concurrent start event for the same key, drops that one sample. Kernel overhead and
  the lost-sample rate under heavy load are not measured yet (M3).
